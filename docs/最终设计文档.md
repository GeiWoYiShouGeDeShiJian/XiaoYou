## 1. 项目定位

**小柚记账**（原「私人记账」）是一款单机、注重隐私的 Android 个人记账应用，定位对标「小星记账」「钱迹」等主流个人记账工具。

核心特点：

- **完全本地化**：数据存于本地 SQLCipher 加密数据库，无 INTERNET 权限，不联网、无服务器。
- **记账体系完整**：支出/收入/转账/借贷四类交易；多账本、多账户、账户分组。
- **扩展属性丰富**：商家、付款状态、报销、退款、优惠、手续费、还款日、标签、成员、图片附件。
- **智能能力**：无障碍 + 通知监听双通道自动记账、语音/文字解析记账、官方账单 CSV 导入、关键词自动分类。
- **管理能力**：预算与阈值提醒、周期自动记账、应收应付、报销、回收站、高级搜索、加密备份、应用锁。

### 2.2 架构分层

采用 **单 Activity + Jetpack Compose + MVVM + Hilt** 架构：

```
UI 层    Compose Screen ⇄ StateFlow 收集（每功能 Screen + ViewModel）
领域层    SaveTransactionUseCase（记账总入口，含重复/余额确认分支）
数据层    Repository（业务编排 + withTransaction 事务）
核心层    DAO（Flow 响应式）← Room + SQLCipher
```

- **UI 无状态**：Screen 只订阅 ViewModel 的 StateFlow，状态变更全部经由 ViewModel 方法。
- **响应式数据流**：DAO 返回 `Flow`，ViewModel `collectLatest`，数据变更自动刷新。
- **金额统一 `Long(分)`**：1 元 = 100 分，全链路避免浮点误差；显示用 `Formatters`，输入用计算器。
- **全局单例**：`CurrentLedgerHolder`（当前账本）、`ThemeStore`（主题）、`HomeUiStore`（首页配置）、`QuickRecordTrigger`（快捷记账事件）。

### 2.3 导航设计

非传统 NavHost，采用 **状态驱动导航容器**（`AppNavGraph`）：

- 底部 3 Tab：首页 / 我的 / 统计。
- 抽屉路由：自动记账、周期记账、报销管理、应收应付、设置、备份、CSV、回收站、搜索、分类管理。
- 记账表单触发：首页 FAB / Widget 快捷记账 / URL Scheme / 编辑。
- URL Scheme `jizhang://record?amount=&type=&category=&note=&account=` 支持预填记账。

## 4. 数据模型设计

数据库版本 **22**（Room + SQLCipher，`exportSchema = true`，17 张表）。

| 实体 | 表名 | 说明 |
|---|---|---|
| `Ledger` | `ledger` | 账本（含封面、图标、本位币、隐藏、软删除） |
| `AccountGroup` | `account_group` | 账户分组 |
| `Account` | `account` | 账户（余额/初始余额 Long 分、币种、计入净资产、隐藏、备注） |
| `LedgerAccount` | `ledger_account` | 账本-账户多对多 |
| `Category` | `category` | 分类（父子两级、收藏、关键词匹配） |
| `Transaction` | `transactions` | 核心交易（见下） |
| `TransactionImage` | `transaction_image` | 图片附件（最多 4 张） |
| `TransactionTag` | `transaction_tag` | 交易-标签关联 |
| `Tag` / `TagGroup` | `tag` / `tag_group` | 标签 + 分组（分组含颜色） |
| `Merchant` / `MerchantGroup` | `merchant` / `merchant_group` | 商家 + 分组 |
| `Member` | `member` | 成员/角色（预置：自己/孩子/父母/亲戚/朋友/家庭公共，含头像与颜色） |
| `Budget` | `budget` | 预算（月/年、结余滚动） |
| `RecurringTemplate` | `recurring_template` | 周期记账模板 |
| `RecordTemplate` | `record_template` | 快捷记账模板（含币种/优惠/标签/应付款/待报销/快速保存等扩展） |
| `AppSetting` | `app_setting` | 键值对 KV 配置 |

### 4.1 `Transaction` 核心字段

- **归属**：`ledgerId`、`accountId`、`toAccountId`（转账目标）、`categoryId`、`memberId` + `memberIds`（多选成员）
- **金额与类型**：`amount`(分)、`type`(INCOME/EXPENSE/TRANSFER/LOAN)、`currency`、`discount`(优惠)、`fee`/`feePayer`(转账手续费/补贴)
- **时间**：`tradeDate`、`createdAt`、`updatedAt`、`dueDate`(借贷还款日)
- **扩展状态**：`paymentStatus`(PAID/UNPAID)、`reimbursementStatus`(NONE/REIMBURSABLE/REIMBURSED)、`refundStatus` + 退款四字段、`loanDirection`(OUT/IN)、`reimburseLinkId`(报销联动)
- **统计开关**：`includeInSummary`(计入结余)、`includeInBudget`(计入预算)
- **溯源**：`source`(MANUAL/VOICE/AUTO_ACCESSIBILITY/AUTO_NOTIFICATION/AUTO_SILENT)、`isRecurringGenerated`、`dedupHash`(去重)、`deletedAt`(软删除)

### 4.2 金额精度设计

- 所有金额字段一律 `Long(分)`；换算/计算用 `AmountCalculator`/`KeypadCalculator`，显示经 `Formatters.centsToYuan`。
- 官方账单解析：金额字符串 `元 → 分` 用 `(it * 100).toLong()` 按位运算，杜绝浮点存储。

## 5. 核心业务规则

| 规则 | 内容 |
|---|---|
| R1 余额联动 | INCOME 账户 +amount；EXPENSE -amount；TRANSFER 源 -、目标 +；LOAN 不联动余额。统一在 `balanceDeltas/applyBalance/reverseBalance` |
| R2 金额单位 | 全库与计算用 Long(分)，显示/输入边界转换 |
| R3 软删除 | 删除置 `deletedAt` 进回收站；超 7 天由 Worker 每日永久删除并回滚余额，临近清理每日通知 |
| R4 账本隔离 | 业务表带 `ledgerId`，按 `CurrentLedgerHolder` 过滤；共享账户关联全部账本 |
| R5 预算 | 月预算 + 上月结余滚动；可用 = 本月预算 + 上月结余；跨 50%/80%/100% 各通知一次（阈值存 KV 防重复） |
| R6 统计范围 | 默认仅聚合 EXPENSE；趋势按 DAY/WEEK/MONTH 桶化 |
| R7 周期补跑 | 到期逐条生成交易并推进 `nextExecuteDate`；重复模板上限 1000 次；生成走 `applyBalance` + `dedupHash` 防重 |
| R8 转账/借贷展示 | 不作为收支聚合，可经 `includeInSummary` 调整结余口径 |
| R9 共享账户约束 | 默认分组不可删；删除账户时联动处理 `ledger_account` |
| R10 去重 | `dedupHash = MD5(accountId + tradeDate + amount + type.name)`；导入/补跑/自动记账据此跳过 |

## 6. 关键机制设计

### 6.1 自动记账（双通道）

**通道一：无障碍服务**（`AutoRecordAccessibilityService`）
- XML 白名单仅微信/支付宝（`packageNames` 系统级隔离，隐私与性能双收）。
- `typeWindowStateChanged` 主信号 + 600ms 防抖 + `typeWindowContentChanged` 补充；`notificationTimeout=300ms` 节流。
- 页面规则引擎（`PageRuleRegistry`）：规则与代码分离，`requiredMarkers` 全命中判定页面；金额按 `textSize` 取主金额，过滤"退款/优惠/券"干扰；商户取标签相邻兄弟节点；单号/时间结构化提取。

**通道二：通知监听**（`AutoRecordNotificationListener`）
- 白名单：支付宝/云闪付/美团/京东/拼多多/抖音/银行；微信刻意排除（通知不带金额）。

**三层防重**：页面级防抖（内存 LRU 10 分钟）→ 用户忽略名单（KV JSON，FIFO 500 条）→ 入库 `dedup_hash`（有单号用 `AUTO|pkg|orderNo` 绝对指纹，无单号用模糊指纹）。

**三种入账模式**：悬浮窗确认（默认）/ 通知确认 / 静默入账（可撤销通知）。
- 悬浮窗：`TYPE_APPLICATION_OVERLAY` + ComposeView，`OverlayLifecycleOwner` 三合一（`performRestore` 必须先于 `ON_CREATE`，顺序颠倒即闪退）；Hilt 经 `EntryPointAccessors` 取用。
- 降级链路：无悬浮窗权限 / 厂商支付保护拦截 → 自动降级通知确认。
- 辅助：识别日志（环形 100 条）、忽略名单管理、来源徽标、掉线自检、受限设置三步引导（Android 13+ 侧载）、ADB 高级修复授权（`WRITE_SECURE_SETTINGS`）。

### 6.2 自定义首页

- `HomeConfig`（Gson 存 `app_setting`，key=`home_config`）：数据一/二/三、统计卡 A/B/C（9 档数据项）、封面、模块显隐/排序、下拉操作、最近交易条数（3/4/5/10）。
- 首页按 `moduleOrder` 动态渲染；数据概览整块可点击进入自定义首页（`clickCoverToSwitchLedger` 开启时改为切账本）。
- 拖拽排序用 `reorderable`；旧配置 `home_hidden_sections` 自动迁移。
- 封面本期支持纯色 / 默认背景（自定义图片列为远期）。

### 6.3 官方账单导入（P1）

- `OfficialBillParser`：先稳健识别编码（UTF-8 严格解码失败回退 GBK，兼容 BOM/UTF-16），再按表头列名动态定位字段（兼容微信 11 列 / 支付宝 16 列、表头行号差异）。
- 平台识别：命中"交易时间+交易对方"→ 微信；"交易号+收/支"→ 支付宝；否则回退通用 CSV。
- 中性账（提现/充值/退款/转账）自动跳过；失败/关闭状态排除；金额列兼容半角/全角括号。

### 6.4 报销与借贷

- 报销：支出标记 REIMBURSABLE → 生成报销款收入（`reimburseLinkId` 双向关联）→ REIMBURSED；报销管理页按状态过滤。
- 借贷：LOAN 交易不联动余额，`loanDirection` 区分借出（应收）/借入（应付），应收应付页按成员分组、右滑标记已还；`settleLoan` 提供结算；支持还款日 `dueDate`。

### 6.5 主题体系

- `ThemeColor` 三色系（ORANGE/BLUE/MINT）+ 深色模式（跟随系统/浅/深）+ SDK S+ 动态取色 + 按账本 `ledgerColor` 配色。
- UI 规范（docs/design.md）：颜色/字号/圆角/间距全部走 Material 3 Token（`colorScheme`/`typography`/`shapes`），设计令牌集中定义（Dimens.kt、AppDataColors.kt），共享组件 AppTopBar/AppCard/AppButton/AppTextField。

## 7. 后台任务设计

| Worker | 调度 | 职责 |
|---|---|---|
| `RecurringWorker` → `RecurringCatchUp` | 每日 00:30（KEEP，非低电量） | 周期记账补跑 |

## 8. 安全与隐私设计

- **数据库加密**：SQLCipher 透明加密；根密钥由 Android Keystore 主密钥 `jizhang_sqlcipher_master` 派生（`KeystoreManager.deriveSqlCipherPassphrase`）。
- **加密备份**：逐表 JSON dump → AES-GCM（PBKDF2-SHA1 200k 迭代 + 随机 salt/iv），格式 `MAGIC JZBK + salt + iv + len + enc`；导入在事务内清空重建（临时关外键，原子）。
- **应用锁**：BiometricPrompt（`BIOMETRIC_WEAK`），状态存 KV。
- **无网络权限**：App 无 INTERNET 权限；自动记账仅读取白名单内页面文本，总开关关闭即完全停止解析。
- **去重与可审计**：`dedup_hash` 防重复入账；识别日志让用户可见每次读取内容。

- **识别稳定性**：微信/支付宝改版会导致自动记账页面规则失效，依赖规则表维护 + 识别日志定位；淘宝主动屏蔽无障碍无法识别；后台被杀（华为/荣耀尤甚）服务失效需保活引导。
- **构建兼容**：Hilt 2.59.2 内置 kotlin-metadata-jvm 仅支持元数据 2.3.0，需强制升级至 2.4.0（已在 build.gradle.kts 固定，勿回退）。

## 12. 开发约定

- 金额一律 `Long(分)`，显示/输入边界转换，绝不用浮点存储。
- 数据库变更必须走 Migration 并注册到 `DatabaseModule`，同时升版本号导出 schema。
- 交易类数据删除优先软删进回收站；影响余额的新增类型必须在 `balanceDeltas/applyBalance/reverseBalance` 同步处理。
- UI 使用 `XxxDomain/XxxDisplay`，不暴露裸 Entity/DAO 结果给 Compose。
- 颜色/字号/圆角/间距一律走 Material 3 Token 与设计令牌，禁止硬编码（见 docs/design.md）。
- 自动记账必须保持"无 INTERNET 权限"的隐私边界。
