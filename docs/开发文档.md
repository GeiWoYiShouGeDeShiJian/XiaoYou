## 1. 项目概览

**小柚记账**（原「私人记账」）是一款单机、注重隐私的 Android 个人记账应用。核心特点：

- **完全本地化**：数据存于本地 SQLCipher 加密数据库，不联网、无服务器，隐私安全。
- **账本多账户**：支持多账本、多账户、账户分组，账本内各业务数据隔离。
- **丰富的记账类型**：支出、收入、转账、借贷四类；支持报销、应收应付、标签、图片附件、成员等扩展属性。
- **统计可视化**：趋势、分类占比、消费排行、收支日历。
- **辅助能力**：语音记账、文字解析、CSV 导入导出、加密备份、周期自动记账、预算阈值提醒、桌面 Widget、应用锁、URL Scheme 快捷记账。

## 4. 应用架构

采用 **单 Activity + Jetpack Compose + MVVM + Hilt 依赖注入** 架构。

```
┌─────────────────────────────────────────────┐
│  UI 层  Compose Screen  ←  StateFlow 收集   │
│    (Home/Record/Statistics/... + 共享组件)   │
├─────────────────────────────────────────────┤
│  ViewModel  (每功能一个)                     │
│    持有 StateFlow + 调用 Repository/UseCase  │
├─────────────────────────────────────────────┤
│  Domain 层  SaveTransactionUseCase          │
├─────────────────────────────────────────────┤
│  Data 层  Repository（事务、余额联动）       │
│      ↓                                       │
│  DAO（Flow 响应式查询）← Room + SQLCipher    │
└─────────────────────────────────────────────┘
```

关键架构约定：

- **UI 无状态**：Screen 只订阅 ViewModel 的 `StateFlow`，所有状态变更通过 ViewModel 方法触发。
- **响应式数据流**：DAO 返回 `Flow`，ViewModel `collectLatest`，数据变更自动刷新 UI。
- **Hilt 注入**：`MoneyBookApp` 用 `@HiltAndroidApp`；Repository / UseCase / 全局组件均 `@Singleton`。所有 DAO 由 `DatabaseModule` 提供。
- **金额单位统一 `Long(分)`**：1 元 = 100 分，避免浮点误差。显示层用 `Formatters` 转元，输入层用计算器转分。
- **导航非传统 NavHost**：见 [9. 导航与入口](#9-导航与入口)。
- **全局状态**：`CurrentLedgerHolder`（当前账本 id，`MutableStateFlow<Long>`）、`ThemeStore`（主题）、`HomeUiStore`（首页卡片显隐）、`QuickRecordTrigger`（快捷记账事件）均为单例，供各层读取。

### 5.4 Repository（`data.repository`，均 `@Singleton`）

| Repository | 关键方法 / 职责 |
|---|---|
| `TransactionRepository` | 核心：`save(new, old, balanceCommit)`、软删 `softDelete`、恢复 `restore`、`importOne`、`settleLoan`、`updateReimbursement`、`deletePermanently`；查询：`observeRecent`/`observeByLedger`/`getByLedger`/`observeTrash`/`search`/`getDomain`/`findByDedupHash`；统计：`homeSummary`/`todayExpense`/`weekExpense`/`countByCategory`/`dailyExpenses`/`statistics` |
| `AccountRepository` | `observeAll` / `getById` / `createAccount` / `updateBalance` |
| `BudgetRepository` | `observeBudgets` / `observeStates` / `compute` / `totalState` / `computeOne`（预算可用额与超支计算） |
| `CategoryRepository` | 分类 CRUD、关键词匹配（含 `rememberKeyword` 记住备注关键词）、收藏、排序 |
| `AccountManagerRepository` | 账户分组/账户 CRUD、共享账户逻辑（事务） |

> Repository 是**业务编排与事务**的边界：余额联动、去重、软删除、账本隔离等都在此层完成，`db.withTransaction` 保证原子性。

### 5.5 防重复机制（R10）

- `dedupHash = MD5(accountId + tradeDate + amount + type.name)` 存于 `Transaction.dedupHash`。
- `importOne()`（CSV 导入）与 `RecurringCatchUp`（周期补跑）都会在插入前按此校验，重复则跳过。
- `SaveTransactionUseCase.checkDuplicate()` 会拦截 UI 层的重复提交。

## 6. 领域层 domain

### 6.1 领域模型（`domain.model`）

UI 与 Repository 之间传递的是 `XxxDomain` 模型（非直接裸 Entity），例如 `TransactionDomain`、`CategoryDomain`、`BudgetDomain`、`AccountDomain`、`RecurringTemplateDomain`、`LedgerDomain`、`AccountGroupDomain`。新增字段时需同步更新领域模型、`getDomain()` 映射与展示模型（`TransactionDisplay`）。

### 6.2 UseCase（`domain.usecase`）

| UseCase | 职责 |
|---|---|
| `SaveTransactionUseCase` | 记账保存的总入口，封装：`checkDuplicate`（重复拦截，返回 `Gate.Duplicate(hash)`）、`needBalanceConfirm`（改账余额确认）、`execute`（含图片关联、标签关联、触发预算检查）、`dedupHash`、`isYesterday`。内部类 `Gate`（Ok/Duplicate）与 `Result`（Success/Cancelled）。 |

> 记账交互涉及”重复确认“、”余额变化确认“、”保存后预算检查“多个分支，`SaveTransactionUseCase` 是理解记账流程的关键起点。

## 7. 核心服务层 core

### 7.1 数据库 `core.database`

- `AppDatabase`：版本 **6**，`exportSchema = true`，注册全部 13 实体 + `@TypeConverters(Converters)`。用 SQLCipher 的 `SqlCipherSupportFactory` 做到 DB 透明加密。
- `DatabaseModule`（`@Module @InstallIn(SingletonComponent)`）：提供 `AppDatabase` 与全部 DAO 的 Provider。
- `DatabaseSeed`：首次启动初始化默认账本「默认账本」、2 个账户分组、10 支出分类 + 3 收入分类，写 `seed_version`。在 `MoneyBookApp.onCreate` 后台线程执行。
- `Migration`：见 [12. 数据库迁移历史](#12-数据库迁移历史)。

### 7.2 加密备份 `core.backup.BackupManager`

- `@Singleton`，跨设备加密备份。
- 导出：逐表 JSON dump（含 null/整数/浮点/文本/Blob）→ 外层 AES-GCM 加密（PBKDF2-SHA1 200k 迭代 + 随机 salt/iv，格式 `MAGIC JZBK + salt + iv + len + enc`）。
- 导入：解密校验 MAGIC → 密码错误提示 → 事务内清空重建各表（临时关外键，原子操作）。
- 旧版 `.bk` 不兼容。

### 7.3 解析器 `core.parser`

- `CsvParser`：CSV 导入/导出（commons-csv），表头「日期/类型/分类/账户/金额/备注/标签」；导出按元，导入解析为分，并按名称解析账户/分类 + 类型映射 + 去重。
- `TextParser`：文字解析，正则提取金额（支持`(＋)?*(元|块)?`），`KeywordMatcher` 按命中数最多自动归类分类。
- `SpeechController`：`SpeechRecognizer` 封装，回调 `onResult(String)` / `onError(Int)`。

### 7.4 安全 `core.security`

- `AppLockManager`：应用锁，`BiometricPrompt`（`BIOMETRIC_WEAK`），状态存 `app_setting`；`isAppLockEnabled` / `setAppLockEnabled` / `isHardwareSupported` / `authenticate`。
- `KeystoreManager`：Android Keystore 主密钥 `jizhang_sqlcipher_master`，`deriveSqlCipherPassphrase()` 派生 SQLCipher 口令（DB 加密根密钥）。

### 7.5 工具 `core.util`

- `AmountCalculator`：计算器精度，四则运算，结果最小 1 分，四舍五入两位小数。`evaluate(expression)` / `toCents(expression)`。
- `KeypadCalculator`：键盘/键盘计算器输入处理（追加数字/小数点/运算符、运算符自动替换）。`digest(current, key)` / `deleteLast`。
- `Formatters`：`centsToYuan` / `yuanText` / `dateYmd` / `dateMd` / `timeHM` / `dateYmdTime` / `parseYmd`。
- `ImageSaver`：图片保存（Uri→internal storage，最大边长 1024px、JPEG 90%）、删除、加载。
- `KeywordMatcher`：关键词 JSON 数组匹配，取命中最多分类。

### 7.6 Widget `core.widget`（Glance）

- `QuickRecordWidget` + `QuickRecordWidgetReceiver`：快捷记账按钮，`actionStartActivity<MainActivity>` 带 `EXTRA_QUICK_RECORD`。
- `OverviewWidget` + `OverviewWidgetReceiver`：展示本月收支 + 预算进度，30 分钟刷新，经 `runBlocking` 读 DB。
- 资源：`res/xml/quick_record_widget_info`（2x1）、`overview_widget_info`（4x2）、`res/layout/widget_initial_layout`。

### 7.7 后台任务 `core.work`

见 [11. 后台任务](#11-后台任务)。

由 `AppNavGraph.BottomNavBar` 渲染：首页(Home)、我的(Person)、统计(DateRange)。

### 9.3 抽屉路由 `DrawerRoutes`

| `SETTINGS` | 设置 |
| `BACKUP` | 数据备份与恢复（占位） |
| `CSV` | 账单导入与导出（占位） |
| `TRASH` | 回收站 |

### 9.4 记账表单触发方式

1. 首页 FAB / 新增按钮 → `showRecord = true`。
2. Widget 快捷记账 → `QuickRecordTrigger.fire()` → `quickRecordEpoch` → 打开表单。
3. URL Scheme → `MainActivity.checkRecordUrl` → `applyPrefill` → `prefillEpoch` → 打开并预填。
4. 编辑 → `editingTarget != null` → 打开表单。

### 9.5 URL Scheme `jizhang://`

- Manifest：`intent.action.VIEW` + `BROWSABLE`，`scheme="jizhang"`。
- 格式：`jizhang://record?amount=35&type=EXPENSE&category=餐饮&note=午餐&account=现金`。
- 参数：`type`(默认 EXPENSE)、`amount`(元，必填)、`category`、`note`、`account`。
- 流程：`MainActivity.checkRecordUrl` → 元转分 → `recordViewModel.applyPrefill(Prefill(...))` → `AppNavGraph` 的 `LaunchedEffect(prefillEpoch)` → `consumePrefill()` + `showRecord`。

### 9.6 Widget 快捷记账入口

- `MainActivity` `singleTop` + `onNewIntent` 处理 `EXTRA_QUICK_RECORD` → `checkQuickRecord` → 延迟 300ms `quickRecordTrigger.fire()`。

### 9.7 应用锁

- 启动时 `AppLockManager.isAppLockEnabled()`；开启则 `lockApp`（先校验硬件支持，再 `BiometricPrompt.authenticate`），通过后执行后续（如 `checkRecordUrl`）。

### 9.8 应用启动初始化（`MoneyBookApp.onCreate`）

1. `NotificationHelper.ensureChannel` 创建通知渠道 `budget_alerts`（预算提醒，IMPORTANCE_DEFAULT）。
2. `RecurringScheduler.schedule`：每日周期补跑 worker。
3. `TrashCleanupScheduler.schedule`：每日回收站清理 worker。
4. 后台线程：打开加密 DB（`openHelper.writableDatabase` 会触发口令派生）→ `databaseSeed.seedIfNeeded()` → `RecurringCatchUp.catchUp(now)`。

## 10. 核心业务规则汇总

> 新增记账/统计/预算相关功能前，务必先读本节，避免破坏既定语义。

### R1 余额联动（`balanceDeltas` / `applyBalance` / `reverseBalance`）
- INCOME：账户 +amount。
- EXPENSE：账户 -amount。
- TRANSFER：源账户 -amount，目标账户 +amount（`toAccountId`）。
- LOAN：不联动余额。

### R2 金额单位
- 全库与计算用 `Long(分)`。展示 `Formatters.yuanText/centsToYuan`，输入 `AmountCalculator/KeypadCalculator.toCents`，CSV 导出按元、导入转分。

### R3 软删除与回收站
- 删除置 `deletedAt`（软删除），`observeTrash` 查回收站；超 7 天由 `TrashCleanupWorker` 每日永久删除并回滚余额；约 3 天内将清理则每日通知提醒。

### R4 账本隔离
- `Transaction/Budget/RecurringTemplate` 含 `ledgerId`；`LedgerAccount` 多对多关联账户；当前账本由 `CurrentLedgerHolder` 全局维护。
- 共享账户 (`Account.isShared`) 关联全部账本，非共享仅关联收个账本。

### R5 预算计算
- 月度预算。可用 = 本月预算 + 上月结余；结余 = 上月预算 - 上月支出；超支允许为负（`over`）。`BudgetRepository.computeOne/totalState`。
- 阈值提醒：跨 50%/80%/100% 各通知一次，已通知阈值存 `app_setting`，避免重复打扰。

### R6 统计范围
- 统计聚合默认仅类型为 **EXPENSE**，转账/借贷自然排除；趋势按 DAY/WEEK/MONTH 桶化，范围（本周周一/本月 1 日/本年 1 月 1 日/自定义起止）。

### R7 周期记账补跑
- 模板到期后由 `RecurringCatchUp` 逐条生成交易并推进 `nextExecuteDate`；重复模板最多 1000 次；到期置 `Long.MAX_VALUE` 避免继续扫描；生成交易走 `applyBalance` 且用 `dedupHash` 防重。

### R8 转账/借贷的展示排除
- 转账在统计/首页不作为收支聚合；金额不计入结余默认 false，形成表结构调整 `includeInSummary` 与 `balanceDeltas`。

### R9 共享账户删除约束
- 默认分组（`is_default`）预设不可删；分组下存在账户时删除返回提示；删除账户时处理 `ledger_account` 关联（`deleteByAccount` 等）。

### R10 去重
- `dedupHash = MD5(accountId + tradeDate + amount + type.name)`；导入与补跑据此跳过重复。

### R11 账本删除与切换
- 删除账本需先断开 `ledger_account` 与业务数据关联；`switch` 更新 `CurrentLedgerHolder`；`setDefault` 用 `LedgerDao.clearDefault` 保证唯一默认。

## 11. 后台任务（WorkManager）

| Worker | 调度 | 职责 |
|---|---|---|
| `RecurringWorker` → `RecurringCatchUp` | 每日 00:30，非低电量，KEEP | 周期记账补跑（见 R7） |

## 12. 数据库迁移历史

`AppDatabase` 当前版本 **6**。任何实体变更必须：
1. 修改 `@Database(version = X)`。
2. 新增 `MIGRATION_X_1_Y` 并 `addMigrations(...)`。
3. 触发 Room schema 导出到 `schemas` 目录（供测试与一致性校验）。

| 版本 | 操作 |
|---|---|
| 1 → 2 | `ALTER TABLE transactions ADD COLUMN to_account_id INTEGER`（转账目标账户） |
| 2 → 3 | `ALTER TABLE ledger ADD COLUMN icon TEXT NOT NULL DEFAULT '📖'`（账本图标） |
| 3 → 4 | `ALTER TABLE category ADD COLUMN is_favorite INTEGER NOT NULL DEFAULT 0`（分类收藏） |
| 4 → 6 | 一次性合并：`merchant`、`payment_status`、`reimbursement_status`、`refund_status`、`member_id`、`member` 表、`loan_direction` |

> 注意：版本 5 未单独保留 Migration，4→6 一步合并补齐。SQLCipher 加密场景下等价 `SupportSQLiteDatabase.execSQL` 即可正常 `ALTER`。

## 16. 开发约定与注意事项

- **金额必须用 `Long(分)`**，任何新金额字段遵循此规则，显示/输入边界转换。
- **数据库变更必须走 Migration**，勿直接改 schema 而无迁移（会破坏已装用户）。
- **账本隔离**：新增业务表涉及记账维度时，务必带 `ledgerId` 并在查询中按 `CurrentLedgerHolder` 过滤。
- **删除优先软删**：交易类数据删除应设 `deletedAt` 进回收站，永久删除交给回收站 Worker。
- **余额联动**：任何影响余额的新增交易类型，必须在 `balanceDeltas/applyBalance/reverseBalance` 中同步处理。
- **展示模型**：UI 使用 `XxxDisplay/XxxDomain`，不要直接暴露裸 Entity/裸 DAO 结果给 Compose。
- **主题**：新页面统一用 `MoneyBookTheme` + `MaterialTheme.colorScheme`，涉及强调色可用 `ChartPalette`。
- **命名与代码风格**：方法间保留空行、逻辑内不空行；注释从简（仅非显然的 WHY）；`string` 资源集中管理（`app_name`=小柚记账）。
- **构建注意**：勿回退 `kotlin-metadata-jvm` 覆盖；升级 AGP/Kotlin/Hilt 时先验证三个版本的元数据兼容性。
- **编译验证**：本环境 `GetDiagnostics` 不可靠，代码改动后由开发者在本地自行编译验证。
